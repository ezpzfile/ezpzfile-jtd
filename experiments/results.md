## 2. 크기가 바뀌면 거부되던 문제 → `JSRV_SegmentInformation`

처음 만든 저장 파일 일부가 「ファイルを読み込むことができません」로 거부됨.
원인: 각 저장소 폴더의 `\x04JSRV_SegmentInformation` 이 그 폴더 안 각 칸의 **크기**를 적어 두는 표였고,
본문 크기가 바뀌었는데 표를 고치지 않았기 때문.

- 구조: `VDA_DOC\0` 머리, u16 LE 필드(14: 첫 항목 위치 0x90, 16: 항목 크기 0x60, 18: 개수),
  항목 = 이름(UTF-16LE 64바이트) + u32 0 + u32 크기 + u32 종류.
- 고침: `cfbw::Tree::fix_segment_info()` 가 저장할 때 표를 다시 계산.
- 확인: 코퍼스 95개 전부를 강제로 다시 쓰기(EZPZJTD_FORCE_REWRITE) → **95/95 열림** (`bisect-cache`).

`tests/save.rs` 와 같은 방식(글자 입력·삭제·줄바꿈·서식·쪽 나누기·표)으로 만든 저장 파일을 뷰어로 전부 열어 봄.

| 현재 엔진 (saved-test2) | 274 | **274/274 열림** (`st2a-cache`, `st2b-cache`) |

자동 테스트(`cargo test` + 코퍼스): 텍스트만 편집 273/285, 서식 포함 281/285, 쪽·표 포함 257/285 세션 저장 성공.
나머지는 **저장을 거부**(안내 문구 표시)한 경우이며, 잘못된 파일을 만든 경우는 없음.
거부하는 편집: 괘선 상자 경계를 넘는 줄 합치기, 루비 안 줄바꿈, 괘선 상자 안 표 삽입.

## 7. 줄 머리는 자기 줄에만 (2026-10-02)

README 화면용 안내문을 一太郎 최신판으로 직접 만들다가(`tools/taro2026/samples/demo.py`), 날짜 줄을 오른쪽 정렬했더니 우리 편집기에서는 그 아래 「各位」와 본문까지 오른쪽으로 붙는 것을 발견했다. 一太郎 화면에서는 왼쪽 정렬이다.

| 시험 | 一太郎이 쓴 것 | 一太郎 화면 |
|---|---|---|
| 문단 셋 중 가운데만 오른쪽 정렬 | 가운데 문단 앞에만 줄 머리(`0024:2`) | 셋째 문단은 왼쪽 |
| 가운데만 들여쓰기 5 | 가운데 문단 앞에만 `0026` | 셋째 문단은 들여쓰기 없음 |
| 가운데만 줄 간격 10mm | 가운데 문단 앞에만 `0020` | 셋째 문단은 보통 |

그래서 규칙을 고쳤다: 줄 머리는 자기 줄만 꾸미고, 머리가 없는 줄은 기본값(왼쪽 정렬, 들여쓰기 없음, 보통 줄 간격)이다. 줄 안에서 글자 뒤에 오는 머리만 다음 줄에 적용된다. 전에는 앞 줄의 상태를 이어받는다고 보았는데 틀렸다(규격서 §4.4). 저장 쪽도 같은 규칙으로 맞췄고, 무작위 편집 저장 성공 수는 고치기 전과 같다(285개 중 L0 271, L1 276, L2 259).
