## 2. 크기가 바뀌면 거부되던 문제 → `JSRV_SegmentInformation`

처음 만든 저장 파일 일부가 「ファイルを読み込むことができません」로 거부됨.
원인: 각 저장소 폴더의 `\x04JSRV_SegmentInformation` 이 그 폴더 안 각 칸의 **크기**를 적어 두는 표였고,
본문 크기가 바뀌었는데 표를 고치지 않았기 때문.

- 구조: `VDA_DOC\0` 머리, u16 LE 필드(14: 첫 항목 위치 0x90, 16: 항목 크기 0x60, 18: 개수),
  항목 = 이름(UTF-16LE 64바이트) + u32 0 + u32 크기 + u32 종류.
- 고침: `cfbw::Tree::fix_segment_info()` 가 저장할 때 표를 다시 계산.
- 확인: 코퍼스 95개 전부를 강제로 다시 쓰기(EZPZJTD_FORCE_REWRITE) → **95/95 열림** (`bisect-cache`).

## 7. 줄 머리는 자기 줄에만 (2026-10-02)

README 화면용 안내문을 一太郎 최신판으로 직접 만들다가(`tools/taro2026/samples/demo.py`), 날짜 줄을 오른쪽 정렬했더니 우리 편집기에서는 그 아래 「各位」와 본문까지 오른쪽으로 붙는 것을 발견했다. 一太郎 화면에서는 왼쪽 정렬이다.

| 시험 | 一太郎이 쓴 것 | 一太郎 화면 |
|---|---|---|
| 문단 셋 중 가운데만 오른쪽 정렬 | 가운데 문단 앞에만 줄 머리(`0024:2`) | 셋째 문단은 왼쪽 |
| 가운데만 들여쓰기 5 | 가운데 문단 앞에만 `0026` | 셋째 문단은 들여쓰기 없음 |

그래서 규칙을 고쳤다: 줄 머리는 자기 줄만 꾸미고, 머리가 없는 줄은 기본값(왼쪽 정렬, 들여쓰기 없음, 보통 줄 간격)이다. 줄 안에서 글자 뒤에 오는 머리만 다음 줄에 적용된다. 전에는 앞 줄의 상태를 이어받는다고 보았는데 틀렸다(규격서 §4.4). 저장 쪽도 같은 규칙으로 맞췄고, 무작위 편집 저장 성공 수는 고치기 전과 같다(285개 중 L0 271, L1 276, L2 259).


## 8. 새 문서를 .jtd로, 서식을 켜는 속성 20 (2026-10-07)

새 문서는 지금까지 .jtd로 저장하지 못했다. 저장이 원본을 고쳐 쓰는 방식이라 바탕 파일이 있어야 하기 때문이다. 공개 원본 `1258443_003.jtd`(문부과학성 서식)에서 빈 문서를 만들어 엔진에 넣었다(`src/blank.jtd`, 12,288바이트, 만드는 법은 `examples/makeblank.rs`).

| 시도 | 一太郎ビューア |
|---|---|
| 저장소 클래스 ID까지 지움 | 문서 없이 빈 창만 뜸 |
| 쪽 기록(1001·1002·100B·1006·100D)을 짧은 새 기록으로 바꿈 | 몇몇 조합에서 뷰어가 죽음 |
| 같은 기록에서 값만 바꿈(여백 30mm, 40자, 줄 간격 600, 40줄, 10.5pt) | 열림 |

빈 문서에 글자, 가운데·오른쪽 정렬, 표, 쪽 나눔, 120줄짜리 긴 글을 넣은 6개가 모두 열렸고 뷰어에서 복사한 글자도 같았다. 그런데 굵게·크기·색·밑줄은 화면에 나오지 않았다.

원인은 서식 속성 20이었다. 같은 글을 줄마다 다른 값으로 써서 뷰어로 열어 보았다.

| 값 | 화면 |
|---|---|
| 크기·색만 씀(20이 없거나 0) | 보통 글자 |
| 20 = `80000000`을 더함 | 크기·색이 나옴 |
| 밑줄 13 = 1, 20 = `80000000` | 밑줄 없음 |
| 13 = 1, 20 = `80000010` | 밑줄(13 = 2이면 굵은 밑줄) |
| 1 = 1 (지금까지 굵게로 알던 값) | 보통 글자 |
| 20 = `84000000` 또는 `88000000` | 굵게 |
| 20 = `90000000` 또는 `A0000000` | 기울임 |
| 20 = `82000000` / `83000000` | 방점(위 / 아래) |
| 20 = `80000008` | 흑백 반전 |
| 20 = `8C000000`, `B0000000`, `BD004000` | 보통 글자(두 비트가 모두 1이면 꺼짐) |

공개 원본 95개에서 서식이 붙은 글자는 모두 20의 맨 위 비트가 켜져 있다. 이전 엔진은 값만 썼다. 원래 서식이 있던 문서에서는 새 글자가 옆 글자의 20을 물려받아 우연히 보였고 서식이 없던 문서(003 등)와 새 문서에서는 보이지 않았다. 저장한 파일이 열리는지와 글자만 비교하고 화면 모양은 보지 않아서 놓친 것이다.

고친 것: 서식을 바꾸면 20의 맨 위 비트를 켠다. 굵게와 기울임은 20의 비트로 쓰고(굵게는 一太郎처럼 1 = 1도 같이 씀), 밑줄은 13과 20의 `10`을 함께 쓴다. 다시 보통 글자가 되면 一太郎처럼 20 = 0을 쓴다. 읽을 때도 20이 꺼져 있으면 서식을 무시한다. 기울임은 이제 .jtd에 저장된다(전에는 경고를 띄우고 보통 글자로 저장했다). 읽는 쪽이 바뀌어 공개 원본 6개(1242621_001 등)의 제목이 굵게 보이는데, 一太郎ビューア 화면과 같다.

확인:

| 묶음 | 결과 |
|---|---|
| 새 문서 6종과 서식 시험 파일 | 一太郎ビューア에서 열리고 굵게·크기·색·밑줄이 보임 |
| 원본(003, 004)에 서식을 넣은 파일 | 보임 |
| 무작위 편집(굵게·기울임·밑줄·색·크기 포함)으로 저장한 공개 원본 24개의 사본 | 65/65 열림, 뷰어에서 복사한 글자 대 우리 엔진 99.5%(36개는 완전히 같음) |
| 브라우저 편집기: 새 문서 → 굵게·기울임·밑줄 → 名前を付けて保存 | .jtd를 고를 수 있고, 저장한 파일이 뷰어에서 열림 |
| 자동 테스트(무작위 편집 세션에 기울임·밑줄 추가) | 저장 성공 수가 고치기 전 엔진과 같음(282 세션 중 L0 273, L1 275, L2 261) |
