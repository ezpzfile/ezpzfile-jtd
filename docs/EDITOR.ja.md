# EZPZ File JTD エディタ設計

**日本語** · [English](EDITOR.en.md) · [한국어](EDITOR.ko.md)

目標: rhwp-studio のように、**エンジンが自分で描く独自エディタ**。画面と操作は、一太郎の利用者が
すぐに使えるように合わせる。
商標・ロゴ・アイコン・固有の色は使わない。合わせるのは配置と操作のしかた（どこに何があり、どのキーが何をするか）だけ。

## 1. 構造

```
┌──────────── ブラウザ / Mac アプリ（WebView） ───────────┐
│ UI（JavaScript、ビルドツールなし）                      │
│  メニューバー・ツールバー・ジャンプパレット             │
│  ツールパレット・ルーラ・ステータスバー・タブ           │
│  隠れた textarea ← キー入力・IME（日本語変換）          │
│  ページごとに <canvas> 1 つ ← 表示リストを描くだけ      │
└───────────────▲───────────────┬─────────────────────────┘
                │ JSON:         │ 命令:
                │ 表示リスト、  │ 文字の挿入、
                │ カーソル位置、│ 太字、…
                │ 書式の状態    │
┌───────────────┴───────────────▼─────────────────────────┐
│ ezpzjtd-core（Rust → WebAssembly）                      │
│  read  : jtd → 文書モデル                               │
│  edit  : カーソル・選択・入力・削除・書式・表・取消     │
│  layout: 字×行の格子配置、禁則、改ページ、表            │
│  export: docx · html · md · txt                         │
└─────────────────────────────────────────────────────────┘
```

- **文書モデルが本当の原本**である。画面はモデルを描いた結果にすぎないため、`contenteditable` の
  不安定さがない。
- レイアウトは一太郎と同じく **文字の格子（字×行）** が基準。既定は A4・40 字 × 36 行・10.5 pt。
  全角は 1 マス、半角は 0.5 マス。
- 日本語入力: 隠れた textarea が変換中の文字（preedit）を受け取ると、エンジンがカーソル位置に下線つきで
  配置する。変換候補のウィンドウがカーソルの横に出るよう、textarea をカーソル位置へ移す。
- 入力のたびに全体を配置し直す（文書は数十 KB なので 1 ms 前後）。JavaScript は **見えているページだけ**
  を描き直す。
- 元に戻す: 編集前の状態のスナップショット、最大 100 回（一太郎の既定値と同じ）。続けて打った文字は 1 回にまとめる。

## 4. 保存

| 形式 | 方法 | 備考 |
|---|---|---|
| **一太郎（.jtd）** | 元の jtd を書き換える（`save.rs`） | jtd から開いた文書のみ。Ctrl+S（上書き保存）の既定 |
| Word（.docx） | モデルから新しく作る（`docx.rs`） | 表・文字飾り・ルビを保持 |
| PDF | 画面に描いたページ + 見えない文字層（`pdf.rs`） | 検索・コピーできる。ボタン 1 つですぐダウンロード |
| HTML・テキスト・Markdown | モデルから | |

**jtd の保存手順**（詳しい規則は `docs/spec/JTD-FORMAT.md` §9）

1. 元のファイルを位置情報つきで読み直す（各文字が元のどの単位から来たか）。
2. 元の文書と編集後の文書を「文字・段落の終わり・表の行・セル」の列に展開して比較（diff）する。
3. 残った文字は元のバイトのまま、消した文字は除き、新しい文字は隣の文字の横に入れる。書式が変わった文字は
   その属性だけを変える。
4. 揃えは段落先頭レコード（0x10）で変える。段落を結合・分割して後ろの段落が受け継ぐ状態が変わる場合は、
   元の状態を書き戻す。
5. 保存した結果を読み直し、編集後の文書と 1 文字ずつ比べる。違っていれば **保存せず**、理由を表示する。
6. 位置キャッシュ（LineMark・PageMark・DocumentTextPositionTables）を削除し、ストリームサイズ表
   （`\x04JSRV_SegmentInformation`）を更新する。

**まだ jtd に保存しない編集**（理由を示して断り、代わりに Word・PDF を勧める）
- 罫線のセル内の行とセル外の行をつなぐ、別々のセルの行どうしをつなぐ
- ルビ・均等割付の文字の途中での改行
- 罫線のセルのすぐ内側・横に新しい表を作る
- 新規文書（白紙から作った文書）を jtd で保存する: 書き換えの元になる原本がないため準備中
- 斜体: jtd の属性番号がわからないため通常の文字として保存し、その旨を知らせる

## 5. まだわからないことによる違い

- 用紙・余白・字×行の設定をまだ読めない。そのため、すべての文書を A4 40×36 で配置する。元の文書と改行位置が
  違うことがある。
- 横罫線の位置がわからない。そのため、表の横線は薄い線で表示する。
- フォント番号を解読していない。そのため、明朝 1 種類で表示する。

## 6. 現在の状態（v0.3、2026-10-01）

**できる**
- 新規作成 / jtd を開く（ドラッグ＆ドロップ・Ctrl+O）/ シートタブ
- 入力: 日本語 IME（変換中の文字を下線で表示）、貼り付け、上書き（Insert）、Tab（表の中では次のセル）
- カーソル: 矢印・Home/End・PageUp/Down・単語単位の移動、クリック・ドラッグ・ダブルクリックでの選択、
  表の中の上下移動は同じ列へ
- 編集: 改行・削除（段落の結合）、選択範囲の置き換え、元に戻す/やり直し（100 回）、繰り返し（Ctrl+R）
- 書式: 太字・斜体・下線・文字サイズ（一覧の段階）・文字色、左/中央/右揃え、改ページ
- 罫線: 表の作成、行の上/下への挿入・削除
- 検索・置換（すべて置換を含む）、文字数、和暦の日付の挿入
- 画面: メニュー（Esc・Alt+文字・矢印で操作）、ツールバー、ジャンプパレット（ページ一覧・文書情報・
  元の保存場所の警告）、ツールパレット、ルーラ、ステータスバー、編集記号、倍率（Ctrl+ホイール）、
  スマホの幅に合わせる
- 保存: **一太郎（.jtd）**（元のファイルを書き換え、一太郎ビューアで検証）、Word（.docx）・
  **PDF（すぐダウンロード、文字検索可）**・HTML・テキスト・Markdown、印刷
- 検証: エンジンのテスト 14 件 + 公開 jtd 40 件にランダム編集 4,000 回 × 5 回を行っても停止なし。
  ブラウザの自動テストで入力・IME・表・保存・メニューを確認

**まだ**
- 新規文書を jtd で保存、罫線モード（マウスで線を引く）、列の挿入/削除・セルの結合
- 縦書き、図、ヘッダー・フッター、字下げ・行間の設定、フォントの選択
- ドラッグ中の自動スクロール、スペルチェック、Mac アプリ化（WebView）

## 7. デザイン（v0.2.1）

配置と操作は一太郎、**見た目は EZPZ File**（ezpzfile.com の PDF・HWP エディタと同じデザイン言語）。

- 色: ezpzfile.com と同じ値。ブランドの青 `#0155ff`、インクの段階（`#0b1020`〜`#f4f6fb`）、
  紙の背景 `#e7eaf1`
- フォント: Pretendard（オンライン時）→ Hiragino Sans / Noto Sans JP
- アイコン: Lucide（サイトと同じセット、ISC ライセンス）
- 上部バー: ロゴ・`JTD エディタ`・ファイル名・メニュー・右側に元に戻す / 開く / 印刷 / 青い `保存` ボタン
  （▾ = 名前を付けて保存）。HWP エディタと同じ位置
- 2 段目にツールバー、3 段目に書式バー（灰色の枠の中にフォント・サイズ・− +）。HWP エディタと同じ形
- 左のジャンプパレットは PDF エディタと同じく **ページのプレビューカード**（現在のページは青い枠）
- 右のツールパレット + 右端の **縦のツール列**（文字・段落・罫線・検索・文字数。PDF エディタのツール列と
  同じ形）。押すとその項目だけを開く
- ステータスバー: `n ページ n 行 n 字 | 全 n ページ | 挿入 | 文字数`・右側に編集記号・幅に合わせる・倍率
- ダイアログと通知はサイトのカード（角の丸み 16px）と濃い色の通知の形
