# EZPZ File JTD 에디터 설계

목표: rhwp-studio처럼 **엔진이 직접 그리는 자체 에디터**. 화면과 조작은 一太郎 사용자가 바로 쓸 수 있게 맞춘다.
상표·로고·아이콘·고유 색은 쓰지 않는다. 배치와 조작 방식(어디에 무엇이 있고 어떤 키가 무엇을 하는지)만 맞춘다.

## 1. 구조

```
┌──────────── 브라우저 / 맥 앱(WebView) ────────────┐
│ UI (JavaScript, 빌드 도구 없음)                     │
│  메뉴바 · 툴바 · 점프팔레트 · 툴팔레트 · 눈금자      │
│  상태표시줄 · 시트탭 · 대화상자                      │
│  숨은 textarea ← 키 입력·IME(일본어 변환)            │
│  <canvas> 쪽마다 하나 ← 표시 목록을 그리기만 함       │
└───────────────▲───────────────┬───────────────────┘
                │ JSON(쪽별 표시 목록,│ 명령(글자 넣기, 굵게, …)
                │ 커서 위치, 서식 상태)│
┌───────────────┴───────────────▼───────────────────┐
│ ezjtd-core (Rust → WebAssembly)                    │
│  read  : jtd → 문서 모델                            │
│  edit  : 커서·선택·입력·삭제·서식·표·되돌리기        │
│  layout: 字×行 격자 배치, 금칙, 쪽 나눔, 표          │
│  export: docx · html · md · txt                    │
└────────────────────────────────────────────────────┘
```

- **문서 모델이 진짜 원본**이다. 화면은 모델을 그린 결과일 뿐이라 `contenteditable`의 불안정함이 없다.
- 레이아웃은 一太郎처럼 **문자 격자(字×行)** 기준. 기본 A4 · 40字 × 36行 · 10.5pt. 전각 1칸, 반각 0.5칸.
- 일본어 입력: 숨은 textarea가 변환 중인 글자(preedit)를 받으면 엔진이 커서 자리에 밑줄로 끼워 배치한다.
  변환 후보 창이 커서 옆에 뜨도록 textarea를 커서 위치로 옮긴다.
- 매 입력마다 전체 다시 배치(문서가 수십 KB라 1ms 안팎), JS는 **보이는 쪽만** 다시 그린다.
- 되돌리기: 편집 전 상태 스냅샷, 최대 100회(一太郎 기본값과 같음). 연속 입력은 한 번으로 묶는다.

## 4. 저장

| 형식 | 방법 | 비고 |
|---|---|---|
| **一太郎 (.jtd)** | 원본 jtd를 고쳐 쓴다 (`save.rs`) | jtd로 연 문서만. Ctrl+S(上書き保存)의 기본값 |
| Word (.docx) | 모델에서 새로 만든다 (`docx.rs`) | 표·글자 꾸밈·루비 유지 |
| PDF | 화면에 그린 쪽 그림 + 보이지 않는 글자층 (`pdf.rs`) | 검색·복사 가능, 버튼 하나로 바로 받기 |
| HTML · 텍스트 · Markdown | 모델에서 | |

**jtd 저장 순서** (자세한 규칙은 `docs/spec/JTD-FORMAT.md` §9)

1. 원본을 위치 정보와 함께 다시 읽는다(글자마다 원본의 몇 번째 단위인지).
2. 원본과 편집본을 "글자·문단 끝·표 줄·칸" 순서열로 펴서 비교(diff)한다.
3. 남은 글자는 원본 바이트 그대로, 지운 것은 빼고, 새 글자는 이웃 글자 옆에 넣는다. 서식이 바뀐 글자는 그 속성만 바꾼다.
4. 정렬은 문단 머리 레코드(0x10)에서 고친다. 문단을 합치거나 나눠서 뒤 문단의 상속 상태가 바뀌면 원래 상태를 다시 넣어 준다.
5. 저장한 결과를 다시 읽어 편집본과 한 글자씩 비교한다. 다르면 **저장하지 않고** 이유를 보여 준다.
6. 위치 캐시(LineMark·PageMark·DocumentTextPositionTables)를 지우고, 스트림 크기 표(`\x04JSRV_SegmentInformation`)를 고친다.

**아직 jtd로 저장하지 않는 편집** (이유와 함께 거부, 그 대신 Word·PDF 권장)
- 罫線 칸의 줄과 바깥 줄을 이어 붙이기, 칸이 다른 줄끼리 잇기
- 루비·균등할당 글자 중간에서 줄바꿈
- 罫線 칸 바로 안·옆에 새 표 만들기
- 새 문서(빈 문서에서 시작)를 jtd로 저장 — 기준이 될 원본이 없어서. 준비 중
- 기울임꼴: jtd 속성 번호를 몰라 보통 글자로 저장하고 알림

## 5. 아직 모르는 것 때문에 생기는 차이

- 용지·여백·字×行 설정을 아직 못 읽는다 → 모든 문서를 A4 40×36으로 배치. 원본과 줄바꿈 위치가 다를 수 있다.
- 가로 괘선 위치를 모른다 → 표의 가로선은 연한 선으로 표시.
- 글꼴 번호 해석 전 → 明朝 하나로 표시.

## 6. 현재 상태 (v0.3, 2026-10-01)

**된다**
- 새 문서 / jtd 열기(끌어놓기·Ctrl+O) / 시트 탭
- 입력: 일본어 IME(변환 중 글자를 밑줄로 표시), 붙여넣기, 덮어쓰기(Insert), Tab(표 안에서는 다음 칸)
- 커서: 화살표·Home/End·PageUp/Down·단어 이동, 마우스 클릭·드래그·더블클릭 선택, 표 안에서 위아래는 같은 열로
- 편집: 줄바꿈·삭제(문단 합치기), 선택 영역 바꾸기, 되돌리기/다시 하기(100회), 繰り返し(Ctrl+R)
- 서식: 太字·斜体·下線·문자 크기(목록 단계)·문자색, 왼쪽/가운데/오른쪽 정렬, 改ページ
- 罫線: 표 만들기, 행 위/아래 삽입·삭제
- 검색·치환(전체 치환 포함), 문자 수, 和暦 날짜 넣기
- 화면: 메뉴(Esc·Alt+문자·화살표 조작), 툴바, 점프팔레트(쪽 목록·문서 정보·원래 저장 경로 경고), 툴팔레트, 눈금자, 상태표시줄, 편집 기호, 배율(Ctrl+휠), 휴대폰 폭 맞춤
- 저장: **一太郎(.jtd)**(원본 고쳐 쓰기, 一太郎ビューア로 검증), Word(.docx)·**PDF(바로 받기, 글자 검색 가능)**·HTML·텍스트·Markdown, 인쇄
- 검증: 엔진 테스트 14개 + 공개 jtd 40개에 무작위 편집 4,000회 × 5회 돌려도 멈춤 없음. 브라우저 자동 테스트로 입력·IME·표·저장·메뉴 확인

**아직**
- 새 문서를 jtd로 저장, 罫線モード(마우스로 선 긋기), 열 삽입/삭제·칸 합치기
- 세로쓰기, 그림, 머리말·꼬리말, 들여쓰기·줄 간격 설정, 글꼴 선택
- 드래그 중 자동 스크롤, 맞춤법, 맥 앱 포장(WebView)

## 7. 디자인 (v0.2.1)

배치와 조작은 一太郎, **모양은 EZPZ File**(ezpzfile.com의 PDF·HWP 편집기와 같은 디자인 언어).

- 색: ezpzfile.com과 같은 값 — 브랜드 파랑 `#0155ff`, 잉크 단계(`#0b1020`~`#f4f6fb`), 종이 바탕 `#e7eaf1`
- 글꼴: Pretendard(온라인일 때) → Hiragino Sans / Noto Sans JP
- 아이콘: Lucide(사이트와 같은 세트, ISC 라이선스)
- 위 막대: 로고 · `JTD エディタ` · 파일 이름 · 메뉴 · 오른쪽에 되돌리기 / 開く / 인쇄 / 파란 `保存` 버튼(▾ = 名前を付けて保存) — HWP 편집기와 같은 자리
- 둘째 줄 도구 막대, 셋째 줄 서식 막대(회색 칸 안에 글꼴·크기·− +) — HWP 편집기와 같은 모양
- 왼쪽 점프팔레트는 PDF 편집기처럼 **쪽 미리보기 카드**(현재 쪽은 파란 테두리)
- 오른쪽 툴팔레트 + 맨 오른쪽 **세로 도구 줄**(文字·段落·罫線·検索·文字数, PDF 편집기의 도구 줄과 같은 모양). 누르면 그 항목만 펼친다
- 상태표시줄: `n ページ n 行 n 字 | 全 n ページ | 挿入 | 文字数` · 오른쪽에 편집 기호 · 폭 맞춤 · 배율
- 대화상자·알림은 사이트의 카드(모서리 16px)·짙은 알림 모양
